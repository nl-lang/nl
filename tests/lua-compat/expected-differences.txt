# Results that differ between the fork and stock LuaJIT, and exactly how.
# One per line, tab-separated:
#   suite   RUNTIME  test name (as test.lua prints it)  SPEC  reason
#   corpus  RUNTIME  corpus file                        SPEC  reason
# RUNTIME is fake, real or any (the runtime the fork was built with: see
# build.sh). SPEC says exactly what differs; anything else fails:
#   added: A B ...       the fork fails the check with got/expected lists
#                        that differ only by these added items (stock passes)
#   first-error-added: A B ...   the same, for the first error of a file run
#                        without the runner (it stops at its first failure)
#   suite                the output is a whole run of test.lua: compared test
#                        by test with the suite entries
#   extra-lines: PATTERN the fork prints the same lines as stock, plus lines
#                        matching the Lua pattern (at least one)
#   fork-fails: PATTERN  the fork fails, its first line matching the pattern
#                        (the exit status may differ); for a suite entry,
#                        stock passes the test and the fork's result matches
#   either-fails: PATTERN   corpus only: one side fails, its first line
#                        matching the pattern, and the other passes with no
#                        output; for a file whose result depends on the heap
#                        layout on stock too
# A suite entry must occur (so that the list stays exact); a corpus entry is
# checked when its file differs.
